Before you get started building your first Ember app, there are a few concepts
you should be familiar with:

* [Node.js](http://www.nodebeginner.org/book.html#javascript-and-nodejs):
A way to run JavaScript outside the browser.
* [npm](https://www.npmjs.com/about): A package manager for Node.js.
* [Bower](http://bower.io/): A package manager for front-end assets.
* [ES6 modules](http://eviltrout.com/2014/05/03/getting-started-with-es6.html):
A module system for JavaScript.
* [Promises](http://www.html5rocks.com/en/tutorials/es6/promises/): A standard
way to represent the result of an asynchronous operation.
* [Web components](https://developer.mozilla.org/en-US/docs/Web/Web_Components):
Reusable, encapsulated user interface building blocks.
* [JSON](http://www.mashery.com/blog/api-data-exchange-xml-vs-json): A data
format based on JavaScript objects.
* [Unit tests](http://code.tutsplus.com/articles/the-beginners-guide-to-unit-testing-what-is-unit-testing--wp-25728): Automated tests for isolated parts of an application.
* [Acceptance tests](http://www.andylindeman.com/acceptance_testing/): Automated
end-to-end tests for entire features of an application.

If you haven't encountered these concepts before, you should familiarize
yourself with them before diving into Ember.
